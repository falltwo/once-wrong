# 真實模型與系統端到端驗收

2026-10-29，Windows／Python 3.12.14，推送前驗收紀錄。全部輸入皆為合成資料；沒有使用保戶資料。原始模型回應、SQLite 與畫面留在本機；本文件僅包含可交接的流程摘要。

## 結果

使用 OpenRouter 的 `deepseek/deepseek-v4-flash`，單次輸出上限 2,048 tokens，沒有模型重試。上傳兩筆壽險承保資料，規則找出一筆 L0302 異動序號錯誤；模型提出把指定格子的 `00001` 改為 `00000`。系統重新檢查整份報表，確認目標錯誤消失且未新增錯誤，才提供可執行修法。模型引用的手冊段落可從前端檢視。

此流程實際呼叫模型一次：輸入 3,357 tokens、輸出 276 tokens，回報費用 US$0.00035181。快取重讀與重啟測試沒有再次呼叫模型。

## 範圍與證據

本次確認的是 Demo 的 `life_underwriting_v1` 規則，以及多檔 `life_filing_v1` 已實作子集的流程。內部確認不等於對外申報；多檔仍有官方規則未實作，系統已明列未評估並擋住確認。

原始回應、SQLite、合成案例、HTTP 驗收摘要及畫面留於忽略的 `logs/live-evaluation/20261029-192152/`。該目錄的 `e2e-summary.json` 記錄 API 流程，`http-summary.json` 記錄真實 HTTP 補驗，`e2e-ui-ai.png` 顯示模型與通過重驗的修正值；沒有序列化金鑰。

## 批次評測依使用者指示停止

原計畫為 390 案例／595 筆錯誤；停止時保留 83 個完整案例、122 筆完整評分，資料庫另有 125 筆已持久化 AI 審核證據。兩個筆數不同，是因為停止當下有案例尚未完成所有問題的評分／日誌寫入。沒有產生正式 `summary.json`，不發布本輪模型品質分數，也不能把部分結果當成完整評測。

最後一次主控台進度為 80 案例、已啟動 123 次模型請求、回報費用約 US$0.090168；這是中途快照，並非最終請求數或結算費用，停止時的在途請求仍可能計費。中止狀態、日誌 hash 及停止後 SQLite 快照留在忽略目錄內。停止後外鍵與稽核鏈檢查通過。

已觀察到模型呼叫失敗、規則通過但不是原值的替代修法，以及證據不足時猜日期的案例，均保留供後續調整。本頁的流程通過不代表所有修法都正確，也不代表完整官方規則已完成。舊 93% 仍只屬於 Gemini 既有評測。
